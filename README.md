# Таро — рабочее место

Локальное приложение для ведения практики: расклады, база знаний по картам, клиенты, события и дневник.
Работает в браузере, данные хранятся в SQLite-файле на этом компьютере. Внешних зависимостей нет.

> **Статус: бета, v0.1.** Приложение уже можно использовать, но возможны ошибки
> и изменения. Перед важной работой делайте резервную копию базы.

Подробное руководство пользователя — в файле **[РУКОВОДСТВО.md](РУКОВОДСТВО.md)**
или **[РУКОВОДСТВО.pdf](РУКОВОДСТВО.pdf)**.

### Как запустить

1. Скачайте архив для своей системы из таблицы выше.
2. Распакуйте его в «Документы» или на рабочий стол.
3. Откройте папку «Таро» и дважды щёлкните:
   - macOS и Linux — «Запустить Таро.command»
   - Windows — «Запустить Таро.bat»

Браузер откроется сам. Если нет — зайдите на **http://localhost:3000**.
Чтобы остановить приложение, закройте чёрное служебное окно.

При первом запуске macOS или Windows могут показать предупреждение о неизвестном
разработчике — это нормально для программ не из App Store:

- **macOS:** правый клик по ярлыку → «Открыть», либо «Системные настройки» →
  «Конфиденциальность и безопасность» → «Всё равно открыть»;
- **Windows:** «Подробнее» → «Выполнить всё равно».

Данные хранятся в папке `data` рядом с приложением. При обновлении замените все
файлы, кроме `data`.

## Запуск из исходников

Нужен Node.js 22.13 или новее (лучше 24 LTS): приложение использует встроенный
модуль `node:sqlite`.

```bash
cd tarot-crm
node server.js
```

Открыть в браузере: **http://localhost:3000**

Для разработки (автоперезапуск при изменении файлов):

```bash
node --watch server.js
```

Порт можно поменять: `PORT=4000 node server.js`. Если порт занят, приложение
само возьмёт следующий свободный и напишет адрес в консоли.

## Сборка архивов для релиза

```bash
node scripts/build-release.mjs
```

Скрипт скачивает официальные бинарники Node.js с nodejs.org, проверяет контрольные
суммы и собирает архивы в `dist/`. Можно выбрать платформы:
`node scripts/build-release.mjs mac-arm64 win-x64`.

## Сборка PDF руководства

Нужны `pandoc` и `weasyprint` (macOS: `brew install pandoc weasyprint`), а также Python
с библиотекой Pillow.

```bash
./scripts/build-guide-pdf.sh
```

Скрипт собирает `РУКОВОДСТВО.pdf` из `РУКОВОДСТВО.md`, режет длинные скриншоты
на страницы и подставляет рабочие ссылки из содержания.

## API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/health` | состояние сервера и версия схемы |
| GET | `/api/stats` | количество записей по разделам |
| GET | `/api/backups` | список последних резервных копий из `data/backups/` |
| POST | `/api/backup` | создать резервную копию базы и вернуть имя файла и размер |
| POST | `/api/backups/:name/restore` | проверить копию, сохранить текущую базу и восстановиться из `:name`; сервер перезапускается |
| GET | `/api/daily-card` | карта дня на дату `?date=`; если ещё не вытянута — `card: null` |
| POST | `/api/daily-card` | вытянуть карту дня на дату; повторный запрос возвращает ту же карту |
| GET | `/api/statistics` | расширенная статистика: статусы раскладов, частота карт, клиенты, темы, теги дневника, итоговые оценки и события |
| GET | `/api/statistics/monthly` | динамика по месяцам: `?months=6` или `?months=12` — расклады, дневник и темы с сравнением двух половин периода |
| GET | `/api/cards` | список карт, фильтры `?arcana=`, `?suit=`, `?q=` |
| GET | `/api/cards/:id` | одна карта целиком, вместе со своими трактовками |
| PATCH | `/api/cards/:id` | личные заметки карты: `notes` |
| POST | `/api/cards/:id/interpretations` | добавить свою трактовку: `orientation`, `title`, `body`, `spread_name` |
| PUT | `/api/interpretations/:id` | изменить свою трактовку, включая `spread_name` |
| DELETE | `/api/interpretations/:id` | удалить свою трактовку |
| GET | `/api/clients` | список клиентов, поиск `?q=` |
| POST | `/api/clients` | создать клиента |
| GET | `/api/clients/:id` | карточка клиента, его расклады и события |
| PUT | `/api/clients/:id` | обновить клиента |
| DELETE | `/api/clients/:id` | удалить клиента |
| GET | `/api/readings` | список раскладов, фильтры `?status=`, `?client_id=`, `?from=`, `?to=`, `?q=`; в каждой строке — последняя оценка итога |
| POST | `/api/readings` | создать расклад вместе с картами |
| GET | `/api/readings/:id` | расклад с картами, позициями, исходными значениями карт, выбранными трактовками, событиями, итогами, оценками позиций и историей трактовок |
| GET | `/api/readings/:id/outcomes` | история оценок итога по раскладу |
| POST | `/api/readings/:id/outcomes` | добавить итог: результат, оценка, комментарий, дата, возврат, уверенность |
| POST | `/api/readings/:id/position-outcomes` | добавить оценку отдельной позиции: `position_index`, результат, оценка, комментарий, дата, возврат, уверенность |
| PUT | `/api/readings/:id` | обновить расклад и заменить карты |
| PATCH | `/api/readings/:id` | изменить только текстовые поля: `interpretation`, `summary` (карты не трогаются) |
| DELETE | `/api/readings/:id` | удалить расклад |
| GET | `/api/events` | список событий, фильтры `?status=`, `?category=`, `?from=`, `?to=`, `?q=` |
| POST | `/api/events` | создать событие |
| GET | `/api/events/:id` | событие и связанные с ним расклады |
| PUT | `/api/events/:id` | обновить событие |
| DELETE | `/api/events/:id` | удалить событие (связи с раскладами удаляются, расклады остаются) |
| POST | `/api/events/:id/readings` | связать событие с раскладом: `reading_id` |
| DELETE | `/api/events/:id/readings/:readingId` | отвязать расклад от события |
| GET | `/api/outcomes/pending` | завершённые расклады без итога и с наступившим возвратом |
| GET | `/api/journal` | записи дневника, фильтры `?q=`, `?from=`, `?to=`, `?client_id=`, `?reading_id=`, `?card_id=`, `?tag=` |
| POST | `/api/journal` | создать запись дневника |
| GET | `/api/journal/:id` | одна запись дневника |
| PUT | `/api/journal/:id` | изменить запись дневника |
| DELETE | `/api/journal/:id` | удалить запись дневника |
| GET | `/api/feedback` | сообщения разработчику, фильтр `?topic=` |
| POST | `/api/feedback` | сохранить сообщение: `topic`, `message`, `page`, `page_title`, `user_agent` |

`/api/statistics` возвращает `totals` (всего записей и статусы раскладов), `cards`
(частота карт с прямыми и перевёрнутыми положениями), `clients` (активность клиентов),
`themes` (темы выпавших карт), `journalTags` (теги дневника), `outcomes`
(последние оценки раскладов, размер выборки и распределение) и `events`
(всего событий, события с результатом, статусы и категории).

`/api/statistics/monthly` возвращает `series` — расклады и записи дневника по месяцам,
`totals` за период, `halves` (месяцы первой и второй половины) и `themes` — темы карт
с числом упоминаний в каждой половине и изменением `delta`. Темы, которые встречались
меньше двух раз за период, не показываются.

Ограничения длины текстов: «Трактовка расклада» и «Выводы» — 2000 символов,
своя трактовка карты — 1000 символов, личные заметки карты — 10000 символов,
текст записи дневника — 3000 символов, описание и результат события — 5000 символов,
текст итога и история трактовок — 5000 символов, сообщение разработчику — 5000 символов.
Лимит проверяется и в поле ввода, и на сервере.

Запись дневника — это дата, заголовок, свободный текст и теги. Дополнительно её можно
связать с клиентом, раскладом и картой. Записи показываются по датам или календарём
по месяцам; в списке рядом с записями видны события. Ищутся по тексту и тегам,
фильтруются по клиенту и периоду. Теги — до 20 штук, каждый до 40 символов.

## Интерфейс

- Тёмная тема и свои выпадающие списки вместо системных: меню выглядят одинаково
  в macOS и Windows, поддерживают клавиатуру и прокрутку длинных списков.
  В длинных списках (например, выбор карты) есть поиск по названию.
- Во всех фильтрах есть кнопка «Сбросить фильтры». Она появляется, только когда
  выбран хотя бы один фильтр.
- В списке раскладов расклад можно удалить, не открывая его.
- В типах расклада есть «Да/Нет»: вопрос, на который можно ответить «да» или «нет».
  Вытягивается одна карта; приложение не выносит вердикт само — ответ читает таролог.
- Свою трактовку карты можно привязать к раскладу: «Да/Нет», «Кельтский крест»,
  один из триплетов или «Для всех раскладов». В форме расклада видны трактовки
  для выбранного расклада и общие.
- Дневник переключается между списком и календарём. В списке записи и события
  сгруппированы по датам; события помечены бейджем «Событие» и статусом.
  В календаре видны и записи, и события:
  у записей золотые метки, у событий — синие. Событие показывается по фактической дате,
  если она заполнена, иначе по планируемой; события без дат в календарь не попадают.
- «+» в клетке дня открывает меню: «Запись в дневнике» или «Событие». Дата подставляется
  в форму, после сохранения приложение возвращает в календарь на этот день.
- Отменённые и архивные события по умолчанию скрыты; их можно показать переключателем
  «Отменённые и архивные». Отдельный переключатель «Показывать события» убирает события
  из сетки, оставляя только записи.
- Месяц, выбранный день, вид и фильтры дневника сохраняются в адресе страницы — ссылку
  можно обновить или вернуться назад без потери вида.
- На «Обзоре» сразу после счётчиков есть компактный календарь: листание месяцев,
  «Сегодня», метки записей и событий и то же меню «+». Клик по дню открывает
  календарь дневника на выбранной дате. Ниже — быстрые действия «Создать событие»
  и «Создать расклад», блоки «Последние события» и «Последние расклады».
- У приложения есть favicon и цвет темы для вкладки браузера.
- Ключевые слова и темы на карточке карты кликабельны: открывают подборку карт
  с этим словом. Поиск в «Базе знаний» учитывает и ключевые слова, и темы.
- Расклад можно экспортировать в PDF: кнопка «Экспорт в PDF» открывает
  предпросмотр в стиле приложения, дальше в диалоге печати — «Сохранить как PDF».
- Кнопка «Экспорт в JSON» скачивает расклад одним файлом: карты, трактовки, итоги,
  оценки позиций, история трактовок и связанные события. Формат удобен для резервной
  копии и переноса данных.
- События ведутся отдельно от раскладов: дата, категория, статус, результат и заметки.
  Событие и расклад связываются в обе стороны, а в карточке клиента видны события,
  связанные с его раскладами.
- На странице расклада есть блок «Итог»: фактический результат, оценка
  («совпало / частично / не совпало / недостаточно информации / пока нельзя оценить»),
  комментарий, уверенность и дата возврата к раскладу. Каждое сохранение добавляет
  новую запись, предыдущие оценки остаются в истории.
- В блоке «Оценки позиций» можно оценить каждую карту отдельно: что произошло,
  насколько совпало, комментарий, уверенность и дата возврата. История по каждой
  позиции только дополняется и не меняет общий итог расклада.
- «История трактовок» хранит первоначальный снимок трактовки и выводов, правки после
  завершения и итоговую трактовку после события. Первоначальный снимок не перезаписывается.
- На странице события видна сводка оценок связанных раскладов, а на обзоре — блок
  «Ожидают оценки» с завершёнными раскладами без итога и раскладами, к которым пора вернуться.
- У имени разработчика в боковом меню есть иконка почты: она открывает окно сообщения.
  Можно выбрать тему — «Баг», «Неточность», «Предложение» или «Другое», — описать ситуацию
  и нажать «Сохранить» (заметка останется в вашей базе) или «Отправить на почту»
  (откроется почтовая программа с готовым письмом на `tarot.feedback@mail.ru`).
  Сохранённые сообщения открываются по ссылке «Сохранённые сообщения» или по адресу
  `#/feedback`.
- В боковом меню под именем разработчика есть кнопка «Резервная копия»: она сохраняет
  снимок базы в `data/backups/`, не останавливая сервер. Рядом видно, когда сделана
  последняя копия, а полный путь и размер — во всплывающей подсказке. Ссылка
  «восстановить» открывает список копий и возвращает базу к выбранному моменту:
  перед заменой приложение само сохраняет текущее состояние и перезапускается.
- На «Обзоре» есть блок «Карта дня». Кнопка «Вытянуть карту дня» выбирает случайную
  карту и положение на сегодня; до конца дня показывается одна и та же карта.
  Из блока можно открыть карту в базе знаний или создать запись в дневнике
  с уже подставленными картой и датой.

Раздел «Поиск» ищет сразу по картам, клиентам, раскладам, событиям и дневнику:
по названиям, заметкам, трактовкам, фактическим результатам, итоговым оценкам,
тегам и привязкам. Вкладка «Статистика» показывает статусы раскладов, распределение
итоговых оценок, события по статусам и категориям, частоту выпадения карт,
активность клиентов, темы карт и теги дневника. Отдельный блок показывает динамику
за последние 6 или 12 месяцев: сколько было раскладов и записей дневника и какие
темы карт стали приходить чаще, а какие реже.

В картах расклада можно передать `interpretation_id` — ссылку на свою трактовку карты
из `/api/cards/:id/interpretations`. Сервер проверяет, что трактовка относится к этой карте,
подходит к её положению (прямому или перевёрнутому) и либо общая, либо совпадает
с раскладом. Если трактовку потом удалить, у расклада останется только карта.

## Изображения карт

Колода Rider–Waite–Smith (1909) находится в общественном достоянии. Картинки уже скачаны
в `public/cards/`. Перекачать или проверить целостность:

```bash
node scripts/fetch-images.js          # докачает только отсутствующие
```

## Резервная копия

Самый простой способ — кнопка **«Резервная копия»** в боковом меню, под именем
разработчика. Она делает целостный снимок базы, не останавливая сервер, и кладёт его
в `data/backups/` с именем вида `tarot-20261030-132042.db`. Рядом с кнопкой видно,
когда сделана последняя копия, а полный путь и размер — во всплывающей подсказке.
Старые копии не удаляются автоматически — их можно хранить сколько нужно.

Ссылка **«восстановить»** рядом с кнопкой открывает список копий. При восстановлении
приложение проверяет файл, сохраняет текущую базу в новую копию, заменяет её выбранной
и перезапускается. Если приложение запущено ярлыком, перезапуск происходит сам;
страница обновляется через несколько секунд.

Все данные — в одном файле `data/tarot.db`. Для ручного бэкапа достаточно скопировать его
(при остановленном сервере) или файлы `data/tarot.db`, `data/tarot.db-wal`, `data/tarot.db-shm` целиком.
Перед копированием лучше остановить сервер, чтобы в WAL не осталось незаписанных изменений.
Папка `data/backups/` в Git не попадает.

## Обратная связь

- **Почта:** tarot.feedback@mail.ru — кнопка «Отправить на почту» в разделе
  «Сообщения разработчику» готовит письмо с версией, схемой базы и браузером.
- **GitHub:** **[Issues](../../issues)** — кнопки «Сообщить о проблеме» и
  «Предложить идею» на той же странице.

Кнопка «Сохранить» оставляет сообщение только в вашей локальной базе: разработчик
его не видит. Это заметка для себя, а не отправка.
